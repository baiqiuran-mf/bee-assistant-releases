# 蜜蜂信息采集

客户消息采集 + 中文回复建议教练。数据全部存本地，只给建议，发送永远人工。

**第一版只做一件事：采集 WhatsApp 新消息。** 后期按这个顺序扩：WhatsApp → Telegram → Instagram → LinkedIn / Facebook。数据库和界面已经把渠道位留好了（`customers.channel`），加新渠道不用改编号规则、不用重建表。

---

## 一、硬边界

这个工具不具备自动发送能力，代码里没有实现任何发送接口。 它只做四件事：收消息、存本地、翻译成中文、给中文建议。

## 三、编号规则

```
3A00050
││└── 5 位序号，00001 ~ 99999
│└─── 字母段，A 用满 99999 后进 B
└──── WhatsApp 账号号，1–5
```

编号绑定的是对方的 WhatsApp 号码，不是昵称——他改名也不影响

编号一经分配永不回收、永不复用

同一个人加了你 1 号和 3 号？会是两个编号（`1A00001` 和 `3A00005`），系统提示疑似重复，你决定合不合并

举例：Mike，旧金山，+1534685245，是 3 号账号的第 50 位客户 → `3A00050`，此后与 Mike 永久绑定。

## 四、每个客户一份档案文档

除了数据库，每个客户还会生成一份可直接打开看的 Markdown 文档：

```
data/customers/Mike_旧金山_3A00050.md
                 └名称┘└地区┘└─ 编号 ─┘
```

文档开头固定是客户信息头：

```markdown
# Mike · 旧金山 · 3A00050

| 项目 | 内容 |
|---|---|
| 编号 | **3A00050** |
| 姓名 | Mike |
| 地区 | 旧金山 |
| 时间差 | 当地时间比北京时间晚 15 小时（当地 UTC-7） |
| 时区 | America/Los_Angeles |
| 电话号码 | 1534685245 |
| 加好友时间 | 2026-09-23 03:11 |
| 所属 WhatsApp 账号 | 3 号 |
| 当前阶段 | Day 2 |
| 情绪 | 有兴趣 |
```

下面是客户档案（生成建议时自动抽取填充）和完整对话记录（英文原文 + 中文翻译）。

几个细节：

时差自动算：填了地区就自动识别时区并算与北京的时差，美国夏令时会自动跟着变（旧金山夏天晚 15 小时、冬天晚 16 小时）

改名会重命名文件：Mike 改成 Mike Zhang，文件自动变成 `Mike Zhang_旧金山_3A00050.md`，编号不变

文档随时可以直接编辑，也可以整份丢给 AI 读

## 五、日常怎么用

| 你想做的事 | 怎么操作 |
|---|---|
| 看新消息 | 左侧红点 = 待处理。点客户，中间栏英文原文 + 灰色中文翻译 |
| 要回复建议 | 右侧点「生成建议」，出三条（各带一个角度）+ 自查提示，同时自动更新客户档案 |
| 看/改客户档案 | 中栏客户名右边空处点**「客户档案」**→ 弹窗；改完点弹窗最上面的**「保存档案」**（填地区会自动带出时区） |
| 让 AI 从对话里填档案 | 中栏客户名右边空处点**「从对话里提取档案」**（就在「客户档案」下面一格），不用先开弹窗 |
| 觉得这条好 | 点「采纳」→ 可以改一改再存 → 存进话术库，以后遇到相似场景优先往这个路子上靠 |
| 觉得不行 | 点「不要这条」或「三条都不行，换一批」→ 记进负样本 → 立刻换一个切入口重出三条 |
| 回完了 | 你在任何地方发出消息，红点自动消失；也可以点「标记已回复」 |
| 改客户资料 | 右边弹窗里直接改，点「保存档案」（填地区会自动带出时区） |
| 没连 WhatsApp / Signal 客户 | 顶栏「＋ 手动录入」：填标识（手机号、Signal 用户名或你给的代号），粘对话一行一条，`我:` 开头算你发的，Ctrl+Enter 录入 |

建议是中文的，英文你自己翻译后发——这是有意的设计，最终发出去的语感是你自己的，不是 AI 的客服腔。

### 手动录入通道（`POST /api/manual`）

不连号也能用整条链路：入库 → 翻译 → 建档案 → 出建议 → 采纳/换思路。Signal 客户、其他 IM、或者只想先练练手，都从这里进。

- **标识决定是不是同一个人**：手机号（纯数字）→ `xxx@c.us`；其他（Signal 用户名、昵称、代号）→ `manual:xxx`。同一个人每次要填一样的，否则会拆成两个客户。
- 一行一条，以 `我:` / `me:` 开头算你发的，其余算客户发的；单条时按 `direction` 字段走。
- 默认按内容去重（最近 30 条里有一模一样的话就跳过），所以重复粘同一段不会产生两份。代价：客户连发两句完全相同的短话，第二句可能录不进来——传 `dedupe: false` 关掉。

### 采纳 / 换思路 的闭环（这软件的重点）

生成建议时会先判断**这个客户现在在第几天**（`knowledge/playbook7d.md` 的七天节奏），然后从当天该用的角度里挑三个各出一条。

- **采纳**：存进 `learned` 表，带上角度、阶段、你改后的原文、你写的"为什么这条好"。下次遇到关键词相似的场景，会作为范例喂给模型——不是照抄，是让风格往这边靠。
- **不采纳**：存进 `rejected` 表，下次换思路时会明确告诉模型"这些路子被否过"，并把原话塞进"不要再出现"清单。同一个角度被否 3 次以上，会直接从角度池里摘掉。
- **换思路**：不只是重跑一次。第 2 次尝试会把温度调高、明确要求"换完全不同的切入口"、避开上一轮全部三条、轮换角度。

话术库是本地 SQLite 里的两张表，不是模型微调——不上传、不训练、随时能改。看积累了多少：`GET /api/learned`。

## 六、7 个 AI 与 5 个服务商

软件一共用 **7 个 AI**，分给 **5 个服务商端口**（`config.yaml` 的 `ai.tasks` / `ai.providers`）：

| # | 任务 | 默认用哪家 | 备注 |
|---|---|---|---|
| ① receive | 抓 WhatsApp 新消息入库 | **不需要 AI** | 采集环节：不调用 AI、不判断语种；中文消息不会被翻译 |
| ② translate | 客户消息英→中 | 混元 hy3 | 只翻客户发来的；本来就是中文的直接跳过 |
| ③ suggest | 中文回复建议 | 混元 hy3 | 可改 Claude 对比 |
| ④ translateReply | 采纳后翻成英文 | **固定 GPT** | 界面不给改，口吻前后一致 |
| ⑤ vision | 看客户发的图片 | vision 端口（留空回落混元） | `hy-vision-2.0-instruct` |
| ⑥ asr | 听客户发的语音 | audio 端口（**必须单独填**） | 混元的 key 调不了语音接口 |
| ⑦ video | 看客户发的视频 | vision 端口 | 接口已留，暂未接 |

服务商与申请地址：混元 <https://console.cloud.tencent.com/tokenhub/models> ·
GPT <https://platform.openai.com/api-keys> · Claude <https://console.anthropic.com/settings/keys> ·
听觉 <https://cloud.siliconflow.cn/account/ak>（视觉可留空，用混元那把 key）。

**想看每个 AI 到底拿什么话去干这件事**：顶栏右侧（AI 状态灯左边）点 **「AI 提示词」**。
左边选任务、右边看它**真正发出去的那份提示词**（系统提示词 / 发给它的内容 / 返回什么 / 注意点），每块可一键复制；
「回复建议」还能展开看知识库四个文件的正文和当天教练块。
提示词只有一份（`src/ai.js` 的 `prompt*` 函数），界面和任务共用，不会变成过期文档。

> **baseUrl 只写到 `/v1` 为止**，不要自带 `/chat/completions`、不要带引号——否则拼出重复路径直接 404
> （这次真踩过，现在代码会自动规范化，并在报错里打出真实请求地址）。

想对比 Claude 时只改一处，代码不用动：

```yaml
suggest:
  provider: anthropic      # 从 hunyuan 改这里
  model: claude-sonnet-5
```

| 环节 | 默认 | 什么时候换 |
|---|---|---|
| translate | hy3 | 量大后换 hy-mt2（混元专用翻译模型，更准更便宜） |
| extract | hy3 | 基本不用换 |
| suggest | hy3 | 建议盲测一次：同一段对话让 hy3 和 claude-sonnet-5 各出三条，你挑哪个更像你 |
| vision | hy-vision-2.0-instruct | 看客户发的宠物照片 |
| asr | hy-asr-3.0-preview | 客户发语音时转文字 |

API 地址和 key 填在 `ai.providers` 里。没填 key 也能跑——消息照常进出库、档案文档照常生成，只是不翻译、不出建议，界面会提示你。

## 七、知识库（决定建议质量的关键，先填这里）

`knowledge/` 下六个文件，这几个要你亲自填：

| 文件 | 填什么 | 重要度 |
|---|---|---|
| `templates.md` | 你自己写得好的真实回复，15–30 条 | ⭐⭐⭐ 最高 |
| `persona.md` | 说话习惯（已按你的情况起草，标了 `[待你确认]` 的地方改掉） | ⭐⭐⭐ |
| `redlines.md` | 红线清单（已填好，可补充你踩过的坑） | ⭐⭐⭐ |
| `playbook7d.md` | 七天推进节奏：每天只做一件事、角度池、发前自检 | ⭐⭐⭐ 建议的方向盘 |
| `products.md` | 尺寸、价格、工期、物流 | ⭐⭐ 填错会前后矛盾 |
| `stories.md` | 哆咪、加州姐姐、洪瑞生师父、工作室（已填，含使用时机） | ⭐⭐ |

`playbook7d.md` 是建议的方向盘：它决定"这个客户现在该聊什么、不该聊什么"。模型每次生成建议都会读它，然后按当天目标挑角度。**如果生成的建议总是跳阶段（还在 Day 1 就开始报价），改这份文件比调提示词管用。**

三个原则：

人设写成"遇到情况怎么做"，不是简历——模型需要行为指令

范例比描述管用十倍——`templates.md` 填得越满，建议越像你

资料按需加载——问价格才带价格表，聊到宠物过世才带哆咪，不一股脑全塞

```
│   ├── ai.js            可插拔 AI 客户端（7 个任务 × 5 个服务商）
│   ├── knowledge.js     知识库按需加载
│   ├── coach.js         阶段判定 + 角度轮换 + 教练上下文
│   ├── learn.js         采纳记忆库（learned / rejected 两张表）
│   ├── yaml-lite.js     零依赖 YAML 兜底（没装 js-yaml 时用）
│   ├── media.js         图片 / 语音后台队列（消息先上界面，AI 后台看/听）
│   ├── session.js       浏览器会话（反检测 + 代理隔离）
│   ├── server.js        本地 HTTP + SSE 推送
│   └── main.js          入口
├── public/              界面（index.html / app.js / style.css）
├── knowledge/           人设、红线、范例、产品、故事、七天剧本
├── test/                ids / db / doc / coach / loop / smoke 自测
└── data/
    ├── assistant.db     你的全部客户数据 + 话术库（定期备份这个）
    ├── customers/       每客户一份档案文档：名称_地区_编号.md
    └── media/           客户发来的图片 / 语音（原文件；AI 看完的中文说明存库）
```

备份就是复制 `data/` 整个目录到移动硬盘。

旧版服务端返回 `app.js` / `style.css` 时没带缓存头，Electron 会把它们存进
`%APPDATA%\wa-assistant\Cache`，导致"改了界面重开窗口还是旧样子"。现在的四道防线：

1. 静态文件统一 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`；
2. `index.html` 里 css / js 带 `?v=__BUILD__`，由服务端替换成 `public/` 三文件的最新修改时间（新增 `src/server.js` 的 `buildStamp()`）；
3. Electron 建窗口前 `webContents.session.clearCache()`；
4. 窗口里按 **F5 / Ctrl+R** = `reloadIgnoringCache()`。

## 十、渠道扩展：现在只做 WhatsApp，坑先留好

`customers.channel` 与 `accounts.channel` 两个字段已经建好（老库自动迁移，默认 `whatsapp`）。加新渠道时要动的地方：

| 渠道 | 标识写法 | 接入方式（到时候再定） |
|---|---|---|
| WhatsApp（第一版） | `14155552671@c.us` | whatsapp-web.js + 浏览器会话（已实现） |
| Telegram | `tg:14155552671` | 官方有 Bot API，还能收；用户端自动化风险高 |
| Instagram | `ig:some_user` | 没有官方接口，只能走浏览器会话，风险最高 |
| LinkedIn / Facebook | `li:xxx` / `fb:xxx` | 同上，且反爬最严 |

**编号规则不变**：`{账号}{字母}{5位序号}`，跨渠道也是同一个账号下顺序发号。同一个人在两个渠道 = 两个编号，靠手机号 / 姓名做疑似重复提示（界面会标 ⚠）。

第一版别急着铺渠道。WhatsApp 跑顺、话术库攒起来之后，再谈第二个——每加一个渠道，维护成本是加倍的，不是加一。

## 十一、风险，再说一次

这属于自动化客户端，违反 WhatsApp 服务条款，有封号风险。先用不重要的号跑，主号别动。

单号最多 1 手机 + 4 个关联设备。

客户数据在你本地硬盘，注意备份和加密。
