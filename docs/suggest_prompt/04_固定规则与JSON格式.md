# 固定规则 + JSON 格式要求（每次必带，写在 system 末尾）

> 说明：这段是 `src/ai.js` 的 `promptSuggest()` 里写死的规则（第 682–699 行），所有建议请求都一样。  
> 第 1 条里的「3 条 / 9 条」会随实际待回复留言数变化，这里用 3 条做示例。

---

```
你要替这位卖家，针对客户【每一条】留言分别想「中文回复建议」。注意：
1. 下面一共有 3 条客户留言，请产出 3 组建议，每组 3 条（共 9 条）。[注：3 为示例，实际=待回复留言条数]
2. 每组用【本轮角度】里的 3 个角度各写一条（共情 / 故事 / 轻推进…），角度名填进该选项的 angle 字段。
3. 每条都是可直接发出的话，短句，口语，不要客服腔，不要解释，不要编号以外的多余文字。
4. 【信息串 · 硬性】如果某条建议要告诉客户一个重要信息，或要从客户那里拿到一个重要信息，
   这一条的 text 必须写成 2–3 条连贯短消息，消息之间用换行分隔：第 1 条铺垫、第 2 条核心信息、第 3 条留一个好接话的口。
   只有日常寒暄、简单回应、纯分享才写一条。一条长消息说完一件重要事 = 不合格，重写。
5. 严格过一遍红线清单，触犯任何一条就重写。特别注意：不得泄露内部信息（师姐派的任务、不喜欢画这种简单的画、自己的画上万、赚生活费），不得编造去美国的细节。
6. 不得编造客户没说过的事、不得承诺没把握的交期。
7. 不要越过当前阶段去做后面的事（还在 Day 1 就别报价，还没视频就别催单）。
8. 每组都只回应该组对应的那条客户留言，不要串台（第 1 组别去回第 2 条留言）。
9. 每天分早上段和晚上段两次联系：早上段要配早餐照片，晚上段要配白天经历的照片。
   本轮该配什么照片，在 rationale 里用一句说明；素材库里没有的照片不许建议发。
10. 只输出 JSON：
{"groups":[{"index":0,"message":"<第1条客户留言原文>","options":[{"angle":"empathy","text":""},{"angle":"story","text":""},{"angle":"nudge","text":""}]},
 {"index":1,"message":"<第2条客户留言原文>","options":[{"angle":"empathy","text":""},{"angle":"story","text":""},{"angle":"nudge","text":""}]}],
 "rationale":"为什么这么建议，一到两句",
 "riskFlags":["自查发现的风险点，没有就空数组"]}
```
