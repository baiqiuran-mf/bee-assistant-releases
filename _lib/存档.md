# 
  WhatsApp 客户助理软件 · 完整对话存档

> 
  
    整理时间：2026-09-23
    用途：把本项目中所有讨论、决策、确定的规则固化成一份可查阅的档案
    关联代码目录：`/workspace/wa-assistant/`

## 
  〇、项目缘起

  用户是独立定制油画卖家（美国客户为主），经营"7 天朋友式销售对话体系"。
  想做一款软件：同时监控多个 WhatsApp 网页窗口 → 读取每个客户的聊天记录 → 自动翻译成中文并存到本地 → 调 AI 按每个客户独立生成中文回复建议 → 用户自己翻译英文、手动发送。

  核心诉求：软件只给建议、永不自动发送；数据全部本地存储；用越便宜的 AI 越好（最终锁定腾讯混元 Hy3）。

## 
  一、逐轮对话纪要（含关键结论）

### 
  第 1 轮｜能否做"多窗口监控 + 自动按客户出回复建议"的软件？

  结论：能。 三条路线：

  A. 人工工作台（手动贴记录出建议）—— 零封号风险，先验证价值

  B. 本地监听助手（多隔离浏览器会话，实时读消息出建议）—— 中风险（违反 WhatsApp ToS）

  C. 官方 Cloud API —— 合规但接管不了个人号历史，做不了朋友式

  推荐：先 A 档验证建议好不好用，再上 B 档。 B 档五层架构：采集层 → 存储层 → 上下文层 → 建议层 → 审核层。

### 
  第 2 轮｜存储层主要存什么？

  结论：存的不是聊天备份，而是"每个客户的记忆"。 六类数据：

  账号元信息（手机号、代理、状态）

  消息原文（方向、时间、图片路径）

  客户档案（抽取的结构化事实，最核心）

  节奏状态（Day 几、时区、是否待回复）

  建议与采纳反馈（用于迭代话术）

  成交结果

  客户档案字段示例：宠物名/品种/是否在世、进度信号、承诺过的报价与工期、客户时区、情绪、共同话题、禁忌。

### 
  第 3 轮｜本地存数据 + AI 能读吗？监视网页新信息怎么做？

  结论：用"数据世界"工作，不靠"激活窗口看屏幕"。 真实触发链路（3–8 秒）：
  监听新消息 → 入库 → 更新档案 → 组装上下文 → 调 AI → 桌面弹窗 → 用户手动发。

  关键纠正：AI 不会自己去翻电脑。 是软件查 SQLite 只挑这一个客户的资料打包发给 API，精确控制 AI 看到什么。跨客户物理隔离。

### 
  第 4 轮｜用 Chrome 打开的网页版能获取聊天记录吗？图片能压吗？本地存储？

  结论：三问皆"能"。 要点：

  工具的浏览器（Puppeteer 自开 Chromium）与用户日常 Chrome 不是一回事，首次需扫码登录，登录态存本地

  文本全量可拉（含历史）；已撤回消息拿不到；语音需额外转写

  图片能下载 + 压缩（最长边 1024px、质量 80、转 WebP），3–5MB → 约 150KB

  本地存储方案：`D:\WAAssistant\` 下分 data / media / sessions / backup

  美国客户数据不出本机，备份整个目录到移动硬盘即可

### 
  第 5 轮｜接管现有 Chrome 麻烦吗？人性化 AI 用哪个？用 API 接管？能智能回答不同客户吗？

  结论：

  接管 Chrome 不推荐（profile 冲突需复制几 GB、调试端口裸奔、连接脆弱、扩展干扰）。扫码是一次性成本，干净实例基本免维护。

  聊天最人性化 AI：Claude（文本自然度最佳）；国产模型英文"本地人味"差一档；本地部署质量明显下降。

  纠正概念：AI 没有"接管"，每次调用都是无记忆的演员。 "记住每个客户"是软件在 SQLite 做的事。智能化靠：固定人设 prompt + 每个客户不同的上下文段 + 塞真实回复范例 + 采纳反馈闭环。

### 
  第 6 轮｜用腾讯的（混元）行不行？自己开浏览器 IP 不对怎么办？装插件隔离？

  结论：

  混元现名 Hy3（7 月发布、8 月全球开放），纯文本、不支持图片、价格极低（约 $0.063/百万输入 token）。用户要中文建议时它反成首选。

  自己开浏览器 IP 反而可控：每实例单独配代理，比接管更干净。代理账密要用 `page.authenticate`，且 Node 调 API 的请求要单独配代理。

  别装浏览器扩展做隔离（无头不支持、扩展本身是特征）。用 `puppeteer-extra-plugin-stealth`（Node 包，不是扩展）消除自动化痕迹。

### 
  第 7 轮｜Hy3 不够用换什么？自己开浏览器不装插件怎么处理？内核是什么？

  结论：

  上 Claude Sonnet 5（日常主力）/ Opus 5（关键节点）。分活干：Haiku 干杂活、Sonnet 出话术、Opus 打关键局。

  反检测四层：stealth + 启动参数 + 时区语言对齐代理 IP + 行为拟人。建议用有头模式（窗口挪到屏外）。

  内核就是谷歌的 Chromium（Blink + V8）。推荐用 Chrome for Testing（真 Chrome 指纹 + 版本锁死不自动更新）。

### 
  第 8 轮｜读取+提醒+存库简单，越便宜 AI 越好；翻译成中文记录；界面显示客户信息；编号 1-5 开头，1 号第一个客户 1A00001

  结论：Hy3 成首选（中文主场）。 界面三栏草图确认。待确认：编号里 A 的含义、自动清理已回复、只翻客户发来的。

### 
  第 9 轮｜A 是 99999 用完用 B；自动清理已回复；Hy3 不好？有没有好的？

  结论：

  编号规则锁定：账号 1 → `1A00001`~`1A99999` → `1B00001`；账号 2 → `2A00001`…

  已回复：自动检测清除 + 手动兜底

  纠正"Hy3 不好"不准确——问题只在英文语感，用户要中文则很能打。推荐 Hy3 翻译+抽取 + Sonnet 5 出中文建议，做成可插拔。知识库按需加载（不一股脑全塞）。

## 
  二、最终锁定的关键规则

### 
  1. 客户编号规则

  5 个 WhatsApp 账号，编号前缀 `1`~`5`

  格式：`{账号}{字母}{5位序号}`，如账号 1 第 1 位 = `1A00001`

  字母 `A` 满 99999 后用 `B`（`1A99999` → `1B00001`），逐位进位

  编号绑定对方号码（JID），不是昵称；一经分配永不回收

  例：Mike / 旧金山 / +1534685245 / 3 号账号第 50 位 = `3A00050`

### 
  2. 客户档案文档

  文件名：`名称_地区_编号.md`，如 `Mike_旧金山_3A00050.md`

  路径：`data/customers/`

  开头固定信息头（六必填）：

```

  ```markdown
  # Mike · 旧金山 · 3A00050

  | 项目 | 内容 |
  |---|---|
  | 编号 | **3A00050** |
  | 姓名 | Mike |
  | 地区 | 旧金山 |
  | 时间差 | 当地时间比北京时间晚 15 小时（当地 UTC-7） |
  | 时区 | America/Los_Angeles |
  | 电话号码 | 1534685245 |
  | 加好友时间 | 2026-09-23 03:11 |
  | 所属 WhatsApp 账号 | 3 号 |
  | 当前阶段 | Day 2 |
  | 情绪 | 有兴趣 |
  ```

```

  时差自动按时区推算（夏令时自动变）；改名自动重命名文件、编号不变

  头部下方：客户档案（AI 抽取）+ 完整对话记录（英文原文 + 中文翻译）

### 
  4. 行为红线

  只给建议，代码里没有自动发送接口

  只翻译客户发来的消息（省一半成本）

  已回复：自动检测（你在别处回了也清红点）+ 手动"标记已回复"兜底

  新消息：桌面弹窗 + 界面红点

  建议呈现：三条候选（保守 / 中性 / 推进）+ 理由 + 越界自查
