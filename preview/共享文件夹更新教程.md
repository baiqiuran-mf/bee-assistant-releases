# 共享文件夹更新 · 完整教程

> 适用：蜜蜂信息采集 v1.5.0
> 你的目标机器：192.168.10.204
> 写教程的机器：192.168.10.46（就是我现在所在的这台）
> 日期：2026-10-08

---

## 第 0 部分：先看这几条实测结论（别跳过）

我刚才从 192.168.10.46 实测了 192.168.10.204，结果如下：

| 检查项 | 实测结果 | 含义 |
|---|---|---|
| ping 192.168.10.204 | 通，延迟 <1ms | 网络没问题 |
| 445 端口（SMB 文件共享） | **开放** | 对方的文件共享功能已开 |
| 80 端口（HTTP） | **关闭** | 共享文件夹**不能**直接当更新源用 |
| 443 端口（HTTPS） | **关闭** | 同上 |
| `net view \\192.168.10.204` | **拒绝访问** | 共享存在，但没给我账号读权限 |

### 🔴 最关键的一条结论（决定你必须怎么做）

**electron-updater 不能直接读 `\\192.168.10.204\share` 这种 SMB 共享路径。**

原因：软件更新走的是 HTTP 协议下载文件，SMB 共享只能在资源管理器里手动双击打开。
所以你只有两条路可选：

| 方案 | 能不能自动更新 | 怎么做 | 推荐 |
|---|---|---|---|
| **方案一：共享文件夹 + 手动下载安装** | ❌ 不能自动 | 共享文件夹放 exe，客户自己去下载双击装 | ★★★★★ 最省事、最不会坏 |
| **方案二：共享文件夹 + 另开一个 HTTP 服务** | ✅ 能自动 | 在 204 上额外开 HTTP 服务，指向同一个文件夹 | ★★★ 要多开一个服务 |

**我的建议：先用方案一。** 因为你的软件现在是内部使用（几个会员/你自己），
共享文件夹手动下载完全够用，而且方案一**零代码改动、零风险**。
等你真需要"一键自动更新"了，再升级到方案二。

## 第 1 部分：在 192.168.10.204 上建立共享文件夹

> ⚠️ 以下步骤**必须在 192.168.10.204 那台电脑上操作**（不是你现在这台 192.168.10.46）。
> 切换方法：让对方在 204 那台机器上按下面做。

### 1.1 选一个存放文件夹

建议放在一个**没有中文、不需要管理员权限**的路径，避免各种权限坑：

```
D:\wa-update
```

**不要**放这些位置：
- `C:\Program Files\...`（要管理员权限）
- 桌面（有时会有权限问题）
- 中文路径（`D:\更新文件夹` 这种，某些工具会乱码）

**怎么建：** 打开文件资源管理器 → 点 `D:` 盘 → 空白处右键 → 新建 → 文件夹 → 改名成 `wa-update`

### 1.2 右键设置共享

1. 右键 `wa-update` 文件夹 → **属性**
2. 切到 **共享** 选项卡
3. 点 **共享...** 按钮
4. 在"共享名"里填：`wa-update`
   （这个名字就是别人访问时用的名字，**只填名字，不要填 `\\192.168.10.204\...` 完整路径**）
5. 点 **共享...** 按钮确认

**这一步做完后，`\\192.168.10.204\wa-update` 这个地址就存在了。**

### 1.3 设置权限（🔴 最容易漏、也是最关键的一步）

同一个属性窗口里，切到 **安全** 选项卡 → 点 **编辑...**

你会看到上半部分是"组或用户名"，下半部分是"权限"。要做两件事：

#### ① 删掉只对 Administrators 生效的默认限制

如果列表里只有 `Administrators`、`SYSTEM`、`Users` 这几个，`Users` 那行通常是**灰色不可改**（灰色=没权限）。

#### ② 点 **添加...**，添加用户

在"选择用户或组"窗口里：

1. 点 **高级...**
2. 点 **立即查找**（会列出这台机器上所有用户和组）
3. 从列表里选 **需要用这个软件的人**，比如：
   - 如果只有你自己用 → 选你自己的登录名
   - 如果给会员用 → 选会员的登录名
   - 想要**任何人都能下**（见下面的注意事项）→ 选 `Everyone`
4. 点 **确定**
5. 回到权限列表，把这个用户的权限改成：
   - 勾选 **读取和执行**
   - 勾选 **列出文件夹内容**（这一项很多人漏掉，漏了会连目录都打不开）
   - **不要**给"写入""修改""删除"—— 客户只需要下载

6. 点 **应用** → **确定**

### 1.4 高级共享（安全选项设置）

回到 **共享** 选项卡，点 **高级共享...**：

- 确认 **共享此文件夹** 是勾上的
- 记下 **共享名**（就是 1.2 里填的那个）
- 点 **权限...**，检查一下 `Everyone` 或刚加的用户是否在列表里
- ⚠️ 如果列表里只有 `Everyone` 但权限是"无"，点进去改成"读取"

### 1.5 🔴 打开防火墙的文件共享端口

204 那台机器如果是 Windows 防火墙，默认可能拦住入站。

**方法 A（图形界面）：**
1. 开始菜单搜「Windows Defender 防火墙」→ 打开
2. 点左边 **允许应用或功能通过防火墙**
3. 点 **更改设置**（要管理员权限）
4. 往下拉，取消勾选 **公用网络** 那一列的 **文件和打印机共享**（勾上 **专用网络** 那一列）
5. 点确定

**方法 B（管理员 PowerShell），在 204 上运行：**
```powershell
# 快速开文件和打印机共享（专用网络）
Set-NetFirewallRule -DisplayGroup "File and Printer Sharing" -Enabled True -Profile Private
```

**怎么确认你的网络是"专用"还是"公用"：**
```powershell
Get-NetConnectionProfile | Select-Object InterfaceAlias, NetworkCategory
```
如果是 `Public`（公用），要么改成专用：
```powershell
Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
```
要么就得同时开放公用网络（不推荐，安全风险大）。

### 1.6 网络发现

同一台机器上，控制面板 → 网络和 Internet → 网络和共享中心 → **更改高级共享设置**

选**专用网络**，把「网络发现」和「文件和打印机共享」都设为**启用**。

也可以用命令行：
```powershell
Set-NetFirewallRule -DisplayGroup "Network Discovery" -Enabled True -Profile Private
```

## 第 2 部分：把更新文件放进去

### 2.1 要放哪几个文件

你项目里的 `release/` 目录就是产物。在 **192.168.10.46**（你现在这台）上打开：

```
E:\WorkBuddy-Projects\wa-assistant\release\
```

里面现在是 4 个版本（1.2.0 / 1.3.0 / 1.4.0 / 1.5.0）加上 `latest.yml`。

**方案一（手动下载）只需要放这 3 个文件：**
```
wa-assistant-setup-1.5.0.exe            ← 安装包（132 MB）
wa-assistant-setup-1.5.0.exe.blockmap   ← 差分更新用（143 KB）
latest.yml                              ← 版本清单（353 字节，告诉软件最新版是多少）
```

**为什么 `latest.yml` 必须一起放：** 软件靠它知道"最新版本是多少、安装包叫什么名字"。
少这个文件，软件会报"更新源配置有问题"。

**方案二（自动更新）还要多放：**
```
wa-assistant-setup-1.5.0.exe.blockmap   ← 增量下载，强烈建议
latest.yml
wa-assistant-setup-1.5.0.exe
latest.yml.blockmap                      ← 清单文件的 blockmap（打包时若没生成见 2.4）
```

### 2.2 怎么复制过去

**方法 A：命令行复制（推荐，快且不会错）**

在你现在这台 192.168.10.46 上：
```bash
net use Z: \\192.168.10.204\wa-update
copy "E:\WorkBuddy-Projects\wa-assistant\release\wa-assistant-setup-1.5.0.exe" Z:\
copy "E:\WorkBuddy-Projects\wa-assistant\release\wa-assistant-setup-1.5.0.exe.blockmap" Z:\
copy "E:\WorkBuddy-Projects\wa-assistant\release\latest.yml" Z:\
net use Z: /delete
```

**方法 B：图形界面**
1. 资源管理器地址栏输入 `\\192.168.10.204\wa-update` → 回车
2. 把 `release/` 里的文件拖进去

**方法 C：先在 204 上建共享，再从 204 反向拉**

### 2.3 复制后必须验证（🔴 别跳）

在 192.168.10.46 上跑这几条，确认文件完整传过去了：

```bash
dir \\192.168.10.204\wa-update
```

**看三件事：**
1. 三个文件都在
2. **exe 的大小和源文件一致**（1.5.0 应该是 `138,569,700` 字节）
3. **blockmap 应该是 `146,844` 字节**

如果 exe 大小对不上，说明复制没完成或者被截断，重新复制。

### 2.4 如果需要 `latest.yml.blockmap`

跑一次打包，electron-builder 通常会自动在 `release/` 生成它：

```bash
cd E:\WorkBuddy-Projects\wa-assistant
rm -f dist/*.7z
ELECTRON_BUILDER_CACHE=E:/WorkBuddy-Projects/_builder-cache npm run pack
```

打完包看 `release/` 里有没有 `latest.yml.blockmap`。有就一起复制过去。

## 第 3 部分（方案一）：客户怎么下载安装 —— 完整流程

这是**零代码改动**的方案，共享文件夹建好、放好文件就能用。

### 3.1 客户第一次装

1. 客户端打开资源管理器
2. 地址栏输入：`\\192.168.10.204\wa-update`
3. 复制 `wa-assistant-setup-1.5.0.exe` 到本机（比如桌面）
4. **双击运行安装**
5. 安装完就能用

### 3.2 以后出新版本你要做的三步

1. 改 `package.json` 里的 `version`（比如 `1.5.0` → `1.6.0`）
2. 跑一次打包
3. 把新版的 3 个文件复制到共享文件夹，**并且必须覆盖 `latest.yml`**

⚠️ **第 3 步里的覆盖 `latest.yml` 是最关键的一步**，不覆盖的话客户端还是显示 1.5.0。

### 3.3 建议：保留旧版本

不要删掉旧版本的 exe。理由：
- 有客户端装到一半失败时，可以重新下旧的
- 可以对比哪个版本有问题

建议这样组织：
```
\\192.168.10.204\wa-update\
  ├── latest.yml                      ← 只放最新的，永远覆盖
  ├── wa-assistant-setup-1.6.0.exe    ← 当前版
  ├── wa-assistant-setup-1.6.0.exe.blockmap
  ├── wa-assistant-setup-1.5.0.exe    ← 旧版留着
  └── wa-assistant-setup-1.5.0.exe.blockmap
```

## 第 4 部分（方案二）：改成自动更新

如果你要"软件里点一下就更新"，需要两件事：
1. 在 192.168.10.204 上开一个 HTTP 服务
2. 把 `package.json` 的 `build.publish` 从 `github` 改成 `generic`

### 4.1 在 204 上开 HTTP 服务

**方法 A：Python（最简单，204 上如果有 Python）**

在 204 上装个 Python，然后：
```bash
cd /d D:\wa-update
python -m http.server 8000 --bind 0.0.0.0
```

**这个窗口关掉服务就停了**，所以要用下面两种方式让它长期跑。

**方法 B：做成 Windows 服务（推荐，能开机自启）**

在 **204** 上下载 [NSSM](https://nssm.cc/)（Non-Suicide Service Manager），
解压到 `D:\nssm\`，然后**管理员 PowerShell** 运行：
```powershell
# 1. 把 python.exe 的绝对路径查出来先
where.exe python

# 2. 安装成服务（把 C:\Python312 换成你实际的路径）
D:\nssm\nssm.exe install WaUpdateHTTP "C:\Python312\python.exe" "-m http.server 8000 --bind 0.0.0.0 --directory D:\wa-update"

# 3. 设置自动启动
D:\nssm\nssm.exe set WaUpdateHTTP Start SERVICE_AUTO_START

# 4. 启动
D:\nssm\nssm.exe start WaUpdateHTTP

# 5. 防火墙放行 8000 端口
netsh advfirewall firewall add rule name="WaUpdateHTTP" dir=in action=allow protocol=TCP localport=8000
```

**方法 C：用现成的 IIS / 小旋风等 HTTP 服务软件**（图形界面，适合不熟命令行的）

**关键点：HTTP 服务的根目录必须直接指向 `D:\wa-update`**，也就是里面能直接看到
`latest.yml` 和 exe，而不是还要再进一层文件夹。

### 4.2 验证 HTTP 服务

在 192.168.10.46 上（也就是你现在这台）打开浏览器，访问：

```
http://192.168.10.204:8000/latest.yml
```

**能看到 latest.yml 的内容 = 成功。** 如果打不开，按顺序排查：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打不开，提示超时 | 防火墙没开 8000 | 跑 4.1 的 `netsh` 那条命令 |
| 打不开，"拒绝连接" | 服务没启动 | 检查 NSSM 服务状态 |
| 能打开但是 404 | HTTP 根目录指错了 | 加 `--directory D:\wa-update` |
| 能打开但是目录列表 | 路径多套了一层 | 同上 |

### 4.3 改 package.json

**只改 `build.publish` 这一处**，把 github 换成 generic：

```json
"publish": [
  {
    "provider": "generic",
    "url": "http://192.168.10.204:8000"
  }
]
```

⚠️ **注意：**
- `url` 末尾**不要加斜杠**
- `url` 是**HTTP 服务端口 8000 的根地址**，不是共享文件夹地址
- 改完必须**重新打包**，否则 `app-update.yml` 里还是旧的 github 配置

### 4.4 还要改一处代码（🔴 必须）

`src/update.js` 里的 `publishTarget()` 函数现在**只认 github**，不认 generic：

```js
function publishTarget(publish) {
  const cfg = Array.isArray(publish) ? publish[0] : publish;
  if (!cfg) return { ok: false, reason: '发布配置为空' };
  const provider = String(cfg.provider || '');
  if (provider === 'github') {
    const owner = String(cfg.owner || '');
    const repo = String(cfg.repo || '');
    if (!owner || !repo) return { ok: false, reason: '仓库地址没配' };
    return { ok: true, url: `https://github.com/${owner}/${repo}`, provider };
  }
  // 🔴 新增：generic（共享文件夹 HTTP 源）
  if (provider === 'generic') {
    const url = String(cfg.url || '').replace(/\/+$/, '');  // 去掉末尾斜杠
    if (!url) return { ok: false, reason: '共享地址没配' };
    if (!/^https?:\/\//i.test(url)) return { ok: false, reason: '共享地址必须以 http:// 或 https:// 开头' };
    return { ok: true, url, provider };
  }
  return { ok: false, reason: `不认识的分发方式：${provider || '（空）'}` };
}
```

**不改会怎样：** 设置页会一直显示"还没配置更新源：provider 不是 github"，
点检查更新直接报错。**这是我实测代码确认的**，不是猜的。

### 4.5 打包 + 测试

```bash
cd E:\WorkBuddy-Projects\wa-assistant
rm -f dist/*.7z
ELECTRON_BUILDER_CACHE=E:/WorkBuddy-Projects/_builder-cache npm run pack
```

打完包后检查 `dist/` 里有没有 `app-update.yml`（NSIS 装包更新是写在 app-update.yml 里的），
或者用 `@electron/asar` 从 `win-unpacked/resources/app.asar` 里读。

**然后测：**
1. 把新包的 exe + blockmap + latest.yml 传到 `D:\wa-update`
2. 装一个旧版（比如 1.4.0）
3. 打开设置页点"检查更新"
4. 看能不能检测到新版本、能不能下载

### 4.6 🔴 方案二的三个真实风险（一定要知道）

| 风险 | 后果 | 应对 |
|---|---|---|
| 204 机器关了或网断了 | 所有客户端都更新不了 | 备用方案：把 GitHub 那份配置留着当备份 |
| HTTP 是明文传输 | 理论上可被中间人篡改安装包 | 局域网内部用风险可接受；**绝不要暴露到公网** |
| 客户端要能访问 204 | 出了同一个局域网就更新不了 | 这个软件本来就是内网用的，符合场景 |

**electron-updater 6.8.9 我已确认内置 `GenericProvider.js`**，所以这条路技术上是通的。

## 第 5 部分：常见问题排查

### 5.1 共享文件夹相关

| 症状 | 原因 | 解决 |
|---|---|---|
| `net view` 显示"拒绝访问" | 没给账号加权限 | 回 1.3 加用户，**别忘了勾"列出文件夹内容"** |
| 能连上但打不开，提示"拒绝访问" | 缺"列出文件夹内容"权限 | 同上，勾上它 |
| 提示"找不到网络路径" | 防火墙或网络发现关了 | 回 1.5、1.6 |
| 能在 204 上访问，其他电脑不行 | 防火墙只对专用网络开放 | 确认 204 的网络类别是专用，或补开放规则 |
| 复制大文件到一半断 | 网络不稳/超时 | 重新复制，用 `robocopy` 支持断点续传 |

**用 robocopy 复制大文件（推荐，断了能续）：**
```bash
robocopy "E:\WorkBuddy-Projects\wa-assistant\release" "\\192.168.10.204\wa-update" wa-assistant-setup-1.5.0.exe latest.yml /Z /R:3 /W:5
```
`/Z` = 可续传模式，`/R:3` = 失败重试 3 次，`/W:5` = 每次等 5 秒。

### 5.2 共享文件夹账号问题

如果访问时提示要输账号密码，在客户端（客户电脑）上：
```bash
net use Z: \\192.168.10.204\wa-update /user:204机器上的用户名 密码
```
把它存起来（下次不用再输）：
```cmd
cmdkey /add:192.168.10.204 /user:用户名 /pass:密码
```

### 5.3 更新不生效

| 症状 | 原因 |
|---|---|
| 软件说"已经是最新版本" | `latest.yml` 没覆盖，或者内容里的 version 还是旧的 |
| 报"更新源配置有问题" | `package.json` 的 publish 配错，或代码里 `publishTarget()` 没支持 generic |
| 下载失败 | HTTP 服务没起，或防火墙 8000 没开 |
| 下载完安装报错 | `latest.yml` 和 exe 不是同一次打包产物（**sha512 对不上**） |

⚠️ **最后一条要特别注意**：`latest.yml` 里记着 exe's sha512。
如果你手工换了一个 exe 进去但没同步更新 `latest.yml`，软件会报校验失败。
**所以永远要同一次打包出来的文件一起复制，别手工拼。**

## 第 6 部分：我的推荐路线

按风险从低到高：

| 步骤 | 做什么 | 风险 | 需要改代码 |
|---|---|---|---|
| **第一步** | 建共享文件夹 + 放 3 个文件 | 无 | 不需要 |
| **第二步** | 自己试一遍：客户端从共享下载安装 | 无 | 不需要 |
| **第三步** | 加 `latest.yml.blockmap`（如果打包生成了） | 无 | 不需要 |
| **第四步** | 确认需要自动更新了 → 改 `publish` + `publishTarget()` | 中 | 要改 2 个文件 |
| **第五步** | 改完重新打包 + 完整测试 | 中 | — |

**建议现在就做第一步和第二步。** 共享文件夹一建好，30 分钟内就能用起来，
不用碰任何代码，出问题也随时能退回现在的 GitHub 方式。
