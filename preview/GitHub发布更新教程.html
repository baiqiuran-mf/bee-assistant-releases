1登录 GitHub

发布 Release 需要 GitHub 账号有权限。仓库挂在 baiqiuran-mf 这个账号下， 所以要用这个账号登录。

方式 A：浏览器登录（推荐，有图形界面）

gh auth login

? What account do you want to log into? GitHub.com
? What is your preferred protocol? GitHub.com via HTTPS
? Authenticate Git with your GitHub credentials? Yes
? How authenticating? Login with a web browser

你的浏览器会自动打开一个页面 → 点「授权」→ 复制页面显示的 8 位验证码回来粘贴

方式 B： Personal Access Token（如果浏览器登录失败）

  1. 浏览器打开 https://github.com/settings/tokens/new
  2. Note 填 wa-update，Expiration 选 90 days
  3. 勾选权限：repo（勾它下面全选的子项）
  4. 点 Generate token → 立刻复制（关掉就再也看不到了）
  5. 回来跑 gh auth login，选 Paste token

验证登录成功：

gh auth status

看到 Logged in to github.com account baiqiuran-mf 就成了。

⚠️ 2026-10-08 实际情况：gh 已装好（2.102.0），但登录卡在你这边。
gh 装完后不会自动进 PATH，如果提示「找不到 gh」，用完整路径：

3发布（一条命令）

在项目目录下跑这一条：

gh release create v1.5.0 ^
  release\wa-assistant-setup-1.5.0.exe ^
  release\wa-assistant-setup-1.5.0.exe.blockmap ^
  release\latest.yml ^
  --title "蜜蜂信息采集 v1.5.0" ^
  --notes "Signal 采集 + 图片解密 + 状态灯" ^
  --latest

参数说明：

v1.5.0
版本号，必须带 v 前缀，且要和 exe 文件名里的版本一致
三个文件
要传的产物，路径用正斜杠或双反斜杠都行
--title
显示在 Release 页面的大标题
--notes
更新说明文字
--latest
标记为最新版（建议加，不加的话客户端可能提示但不弹窗）
💡 以后发新版只有版本号变：改 package.json 的 version → 重新打包 → 跑这条命令（版本号和文件名都换新）。
⚠️ 常见失败：
  • HTTP 404 → 仓库名拼错了，或登录的账号没权限
  • HTTP 403 → 登录的账号不是 baiqiuran-mf，或者 token 权限不够
  • release already exists → 已经有 v1.5.0 了。加 --clobber 覆盖：
    gh release create v1.5.0 ... --clobber
  • 文件找不到 → 当前目录不对，要先 cd 到项目根目录

5客户端怎么更新

发布成功后，不需要做任何客户端操作 —— 客户在软件里点「检查更新」就会自动发现。

自动更新的流程（软件内部自动完成）：

  1. 软件读 package.json 知道自己是 1.5.0
  2. 去 GitHub 拉 latest.yml，看到最新是 1.5.0
  3. 版本相同 → 显示「已经是最新版本」
  4. （以后发 1.6.0 时）版本更高 → 自动下载 → 显示进度 → 提示安装

注意软件里的两个保护（之前设计的，不是 bug）：

  • 开发模式下不能更新 —— 必须打成 exe 才有更新功能
  • 正在采集客户消息时不自动重启 —— 会提示「采集结束后再点一次」，这是故意的，避免丢消息

6以后发新版的完整流程

  1. 改 package.json 的 version：1.5.0 → 1.6.0
  2. 更新 CHANGELOG.md
  3. 打包：rm -f dist/*.7z 然后 set ELECTRON_BUILDER_CACHE=E:/WorkBuddy-Projects/_builder-cache + npm run pack
  4. 发布：gh release create v1.6.0 release\wa-assistant-setup-1.6.0.exe release\wa-assistant-setup-1.6.0.exe.blockmap release\latest.yml --title "..." --notes "..." --latest
  5. 验证：gh release list + 浏览器打开 Releases 页

不用 gh 的替代方案（网页手动上传）

如果不想用命令行，也可以在网页上传：

  1. 浏览器打开 https://github.com/baiqiuran-mf/bee-assistant-releases/releases/new
  2. 点 Create a new release
  3. 选标签：点 Choose a tag name → 输入 v1.5.0 → 选 Create new tag on publish
  4. 填 Release 标题：蜜蜂信息采集 v1.5.0
  5. 填说明
  6. 把 3 个文件拖到灰色上传区（可以一次拖多个）
  7. 勾上 Set as a pre-release 不要勾；Set as the latest release 要勾
  8. 点 Publish release
⚠️ 网页上传时最容易漏的：latest.yml 这个文件名字很普通，容易被当成无关文件。 必须确认 3 个文件都上传成功，少一个客户端就更新不了。

常见问题

症状原因和解决
客户端说「已经是最新版本」但明明有新版新 Release 没勾 Set as the latest release，或没传 latest.yml
点检查更新报网络错误检查这个地址能不能打开：https://github.com/baiqiuran-mf/bee-assistant-releases/releases/latest/download/latest.yml

为什么 GitHub 比共享文件夹好（你这个场景）：
① 不用在 204 上开防火墙、设权限、建账号；② 客户端在哪都能更新，不限局域网； ③ 有历史版本记录，能回滚；④ 已经有差分更新（blockmap），更新只下载变化部分，快。
