0先看这几条实测结论（别跳过）

我从 192.168.10.46 实测了 192.168.10.204，结果如下：

检查项实测结果含义
ping 192.168.10.204通，<1ms网络没问题
445 端口（SMB 文件共享）开放对方的文件共享功能已开
80 端口（HTTP）关闭共享文件夹不能直接当更新源用
443 端口（HTTPS）关闭同上
net view \\192.168.10.204拒绝访问共享存在，但没给我账号读权限

🔴 最关键的一条结论（决定你必须怎么做）

electron-updater 不能直接读 \\192.168.10.204\share 这种 SMB 共享路径。

原因：软件更新走的是 HTTP 协议下载文件，SMB 共享只能在资源管理器里手动双击打开。所以你只有两条路：

方案一：共享文件夹 + 手动下载安装

不能自动更新

共享文件夹放 exe，客户自己去下载双击装。

推荐 ★★★★★ 最省事、最不会坏、零代码改动。

方案二：共享 + 另开 HTTP 服务

能自动更新

在 204 上额外开一个 HTTP 服务，指向同一个文件夹。

★★★ 要多开一个服务，多改 2 个文件。

我的建议：先用方案一。你的软件现在是内部使用（几个会员/你自己），共享文件夹手动下载完全够用，而且零代码改动、零风险。等真需要「一键自动更新」了，再升级到方案二。

1在 192.168.10.204 上建立共享文件夹

⚠️ 以下步骤必须在 192.168.10.204 那台电脑上操作（不是你现在这台 192.168.10.46）。

1.1 选一个存放文件夹

建议放在一个没有中文、不需要管理员权限的路径：

D:\wa-update

不要放这些位置：

  • C:\Program Files\...（要管理员权限）
  • 桌面（有时会有权限问题）
  • 中文路径（D:\更新文件夹 这种，某些工具会乱码）

怎么建：文件资源管理器 → 点 D: 盘 → 空白处右键 → 新建 → 文件夹 → 改名成 wa-update

1.2 右键设置共享

  1. 右键 wa-update 文件夹 → 属性
  2. 切到 共享 选项卡
  3. 点 共享... 按钮
  4. 在「共享名」里填：wa-update
    这个名字就是别人访问时用的名字，只填名字，不要填完整路径
  5. 点 共享... 确认

做完后，\\192.168.10.204\wa-update 这个地址就存在了。

1.3 设置权限（🔴 最容易漏、也最关键）

同一个属性窗口，切到 安全 选项卡 → 点 编辑...

① 先看上半部分「组或用户名」：如果只有 Administrators / SYSTEM / Users，Users 那行通常是灰色不可改。

② 点「添加...」添加用户：

  1. 点 高级...
  2. 点 立即查找（列出这台机器上所有用户和组）
  3. 选需要用这个软件的人：
    只有你自己用 → 选你自己的登录名；给会员用 → 选会员的登录名；想让任何人都能下 → 选 Everyone
  4. 点 确定
  5. 回到权限列表，把权限改成：
    ☑ 读取和执行
    ☑ 列出文件夹内容 这一项很多人漏，漏了连目录都打不开
    ☐ 不要给「写入」「修改」「删除」—— 客户只需要下载
  6. 点 应用 → 确定

1.4 高级共享（安全选项设置）

回到 共享 选项卡 → 点 高级共享...

  • 确认 共享此文件夹 是勾上的
  • 记下 共享名（就是 1.2 填的那个）
  • 点 权限...，检查 Everyone 或刚加的用户是否在列表里
  • ⚠️ 如果列表里只有 Everyone 但权限是「无」，点进去改成「读取」

1.5 🔴 打开防火墙的文件共享端口

如果 204 是 Windows 防火墙，默认可能拦住入站。

方法 A（图形界面）：

  1. 开始菜单搜「Windows Defender 防火墙」→ 打开
  2. 点左边 允许应用或功能通过防火墙
  3. 点 更改设置（需管理员权限）
  4. 往下拉，取消勾选「公用网络」那一列的 文件和打印机共享，勾上「专用网络」那一列
  5. 点确定

方法 B（管理员 PowerShell，在 204 上运行）：

Set-NetFirewallRule -DisplayGroup "File and Printer Sharing" -Enabled True -Profile Private

怎么确认网络是「专用」还是「公用」：

Get-NetConnectionProfile | Select-Object InterfaceAlias, NetworkCategory

如果是 Public，要么改成专用：

Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private

要么就得同时开放公用网络（不推荐，安全风险大）。

1.6 网络发现

控制面板 → 网络和 Internet → 网络和共享中心 → 更改高级共享设置

选专用网络，把「网络发现」和「文件和打印机共享」都设为启用。也可以用命令行：

Set-NetFirewallRule -DisplayGroup "Network Discovery" -Enabled True -Profile Private

2把更新文件放进去

2.1 要放哪几个文件

你项目里的 release/ 目录就是产物。在 192.168.10.46（你现在这台）上打开：

E:\WorkBuddy-Projects\wa-assistant\release\

方案一（手动下载）只需要 3 个文件：

文件作用
wa-assistant-setup-1.5.0.exe安装包（132 MB）
wa-assistant-setup-1.5.0.exe.blockmap差分更新用（143 KB）
latest.yml版本清单（353 字节）—— 告诉软件最新版是多少
为什么 latest.yml 必须一起放：软件靠它知道「最新版本是多少、安装包叫什么名字」。少这个文件，软件会报「更新源配置有问题」。

方案二（自动更新）还要多一个：latest.yml.blockmap（打包时若没生成，见 2.4）

2.2 怎么复制过去

方法 A：命令行（推荐，快且不会错） —— 在 192.168.10.46 上运行：

net use Z: \\192.168.10.204\wa-update
copy "E:\WorkBuddy-Projects\wa-assistant\release\wa-assistant-setup-1.5.0.exe" Z:\
copy "E:\WorkBuddy-Projects\wa-assistant\release\wa-assistant-setup-1.5.0.exe.blockmap" Z:\
copy "E:\WorkBuddy-Projects\wa-assistant\release\latest.yml" Z:\
net use Z: /delete

方法 B：图形界面 —— 资源管理器地址栏输入 \\192.168.10.204\wa-update → 回车 → 把 release/ 里的文件拖进去。

方法 C：用 robocopy 传大文件，支持断点续传（断了能接着传）：

robocopy "E:\WorkBuddy-Projects\wa-assistant\release" "\\192.168.10.204\wa-update" ^
  wa-assistant-setup-1.5.0.exe latest.yml /Z /R:3 /W:5

/Z 可续传、/R:3 失败重试 3 次、/W:5 每次等 5 秒。

2.3 复制后必须验证（🔴 别跳）

dir \\192.168.10.204\wa-update

看三件事：

  1. 三个文件都在
  2. exe 的大小和源文件一致（1.5.0 应该是 138,569,700 字节）
  3. blockmap 应该是 146,844 字节

大小对不上说明复制没完成或被截断，重新复制。

2.4 如果需要 latest.yml.blockmap

跑一次打包，electron-builder 通常会自动生成：

cd E:\WorkBuddy-Projects\wa-assistant
rm -f dist/*.7z
ELECTRON_BUILDER_CACHE=E:/WorkBuddy-Projects/_builder-cache npm run pack

打完包看 release/ 里有没有 latest.yml.blockmap。有就一起复制过去。

3方案一：客户怎么下载安装

这是零代码改动的方案，共享文件夹建好、放好文件就能用。

3.1 客户第一次装

  1. 打开资源管理器
  2. 地址栏输入 \\192.168.10.204\wa-update → 回车
  3. 把 wa-assistant-setup-1.5.0.exe 复制到本机（比如桌面）
  4. 双击运行安装
  5. 装完就能用

3.2 以后出新版本你要做的三步

  1. 改 package.json 里的 version（比如 1.5.0 → 1.6.0）
  2. 跑一次打包
  3. 把新版 3 个文件复制到共享，并且必须覆盖 latest.yml
第 3 步里「覆盖 latest.yml」是最关键的一步，不覆盖的话客户端还是显示 1.5.0。

3.3 建议：保留旧版本

不要删掉旧版本的 exe（装到一半失败时能重新下旧的，也能对比哪个版本有问题）：

\\192.168.10.204\wa-update\
  ├── latest.yml                      ← 只放最新的，永远覆盖
  ├── wa-assistant-setup-1.6.0.exe    ← 当前版
  ├── wa-assistant-setup-1.6.0.exe.blockmap
  ├── wa-assistant-setup-1.5.0.exe    ← 旧版留着
  └── wa-assistant-setup-1.5.0.exe.blockmap

4方案二：改成自动更新

需要两件事：① 在 204 上开一个 HTTP 服务　② 把 build.publish 从 github 改成 generic

4.1 在 204 上开 HTTP 服务

方法 A：Python（最简单）

cd /d D:\wa-update
python -m http.server 8000 --bind 0.0.0.0

这个窗口关掉服务就停了

方法 B：做成 Windows 服务（推荐，能开机自启）

在 204 上下载 NSSM，解压到 D:\nssm\，然后管理员 PowerShell 运行：

# 1. 先查 python.exe 的绝对路径
where.exe python

# 2. 安装成服务（把 C:\Python312 换成你实际的路径）
D:\nssm\nssm.exe install WaUpdateHTTP "C:\Python312\python.exe" ^
  "-m http.server 8000 --bind 0.0.0.0 --directory D:\wa-update"

# 3. 设置自动启动
D:\nssm\nssm.exe set WaUpdateHTTP Start SERVICE_AUTO_START

# 4. 启动
D:\nssm\nssm.exe start WaUpdateHTTP

# 5. 防火墙放行 8000 端口
netsh advfirewall firewall add rule name="WaUpdateHTTP" dir=in action=allow protocol=TCP localport=8000

方法 C：用现成的 IIS / 小旋风等图形界面 HTTP 服务软件（适合不熟命令行）。

关键点：HTTP 服务的根目录必须直接指向 D:\wa-update，也就是打开就能看到 latest.yml 和 exe，不要再多套一层文件夹。

4.2 验证 HTTP 服务

在 192.168.10.46 上用浏览器访问：

http://192.168.10.204:8000/latest.yml

能看到 latest.yml 的内容 = 成功。打不开就按下表排查：

现象原因怎么办
超时防火墙没开 8000跑 4.1 的 netsh 那条命令
「拒绝连接」服务没启动检查 NSSM 服务状态
能打开但 404HTTP 根目录指错了加 --directory D:\wa-update
能打开但是目录列表路径多套了一层同上

4.3 改 package.json

只改 build.publish 这一处，把 github 换成 generic：

"publish": [
  {
    "provider": "generic",
    "url": "http://192.168.10.204:8000"
  }
]
  • url 末尾不要加斜杠
  • url 是 HTTP 服务端口 8000 的根地址，不是共享文件夹地址
  • 改完必须重新打包，否则 app-update.yml 里还是旧的 github 配置

4.4 还要改一处代码（🔴 必须）

src/update.js 里的 publishTarget() 现在只认 github，不认 generic：

function publishTarget(publish) {
  const cfg = Array.isArray(publish) ? publish[0] : publish;
  if (!cfg) return { ok: false, reason: '发布配置为空' };
  const provider = String(cfg.provider || '');
  if (provider === 'github') {
    const owner = String(cfg.owner || '');
    const repo = String(cfg.repo || '');
    if (!owner || !repo) return { ok: false, reason: '仓库地址没配' };
    return { ok: true, url: `https://github.com/${owner}/${repo}`, provider };
  }
  // 🔴 新增：generic（共享文件夹 HTTP 源）
  if (provider === 'generic') {
    const url = String(cfg.url || '').replace(/\/+$/, '');  // 去掉末尾斜杠
    if (!url) return { ok: false, reason: '共享地址没配' };
    if (!/^https?:\/\//i.test(url)) return { ok: false, reason: '共享地址必须以 http:// 或 https:// 开头' };
    return { ok: true, url, provider };
  }
  return { ok: false, reason: `不认识的分发方式：${provider || '（空）'}` };
}
不改会怎样：设置页会一直显示「还没配置更新源：provider 不是 github」，点检查更新直接报错。这是我实测代码确认的，不是猜的。

4.6 🔴 方案二的三个真实风险

风险后果应对
204 机器关了或网断了所有客户端都更新不了把 GitHub 那份配置留着当备份

5常见问题排查

5.1 共享文件夹相关

症状原因解决
net view 显示「拒绝访问」没给账号加权限回 1.3 加用户，别忘勾「列出文件夹内容」
能连上但打不开，提示「拒绝访问」缺「列出文件夹内容」权限同上，勾上它
「找不到网络路径」防火墙或网络发现关了回 1.5、1.6
204 上能访问，其他电脑不行防火墙只对专用网络开放确认 204 的网络类别是专用，或补开放规则
复制大文件到一半断网络不稳/超时用 robocopy /Z 支持断点续传

5.2 访问时提示要账号密码

net use Z: \\192.168.10.204\wa-update /user:204机器上的用户名 密码

把它存起来（下次不用再输）：

cmdkey /add:192.168.10.204 /user:用户名 /pass:密码

5.3 更新不生效

症状原因
软件说「已经是最新版本」latest.yml 没覆盖，或内容里 version 还是旧的
报「更新源配置有问题」package.json 的 publish 配错，或 publishTarget() 没支持 generic
下载失败HTTP 服务没起，或防火墙 8000 没开
下载完安装报错latest.yml 和 exe 不是同一次打包产物（sha512 对不上）
最后一条要特别注意：latest.yml 里记着 exe 的 sha512。如果你手工换了一个 exe 进去但没同步更新 latest.yml，软件会报校验失败。所以永远要同一次打包出来的文件一起复制，别手工拼。
